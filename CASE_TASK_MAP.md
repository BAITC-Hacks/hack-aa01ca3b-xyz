# CASE Task Map — HackAlem AI

Рабочая карта обязательного кейса и распределения работ на троих. Участники пока обозначены номерами: впишите имена команды. Поручения из примеров организаторов в `data/samples/` — тестовые данные для ИИ и оценки качества, а не задачи, которые участники команды должны исполнить.

## Цель кейса

По записи совещания на русском, казахском или смешанном языке получить транскрипт с говорящими, проверяемый список поручений (кто, что, срок), саммари и файл протокола. Аудио и текст обрабатываются локально; внешние облачные ИИ API запрещены. Интеграции с Teams/Zoom/Meet и СЭД, рассылка уведомлений, голосовая биометрия и промышленный Docker-контур в обязательный MVP не входят.

## Распределение между тремя участниками

Зоны разделены по основным компонентам. Каждый владелец отвечает за проверку своей части и исправления; объединение и финальный показ — общая работа.

| Участник | Роль и зона ответственности | Результат и критерий готовности | Состояние в репозитории |
|---|---|---|---|
| Участник 1 — вписать имя | **Аудио, распознавание и диаризация.** Приём аудио/видео и запись с микрофона; подготовка аудио; распознавание RU/KK/смешанной речи локальными моделями; разметка говорящих и привязка реплик ко времени. Подготовить синтетическую запись и проверить качество речи/спикеров. | `data/samples/synthetic_meeting.mp3` проходит конвейер; есть транскрипт с метками языка, таймкодами и голосами; модели работают без внешнего API. | **Реализовано.** `app/services/media.py`, `app/services/stt.py`, `app/services/diarize.py`, `scripts/download_models.py`. В журнале указано 4 из 4 голосов на синтетической записи. Финальный прогон командой на демонстрационном компьютере — перед показом. |
| Участник 2 — вписать имя | **ИИ-анализ и качество.** Локальный Ollama; восстановление участников по обращениям; извлечение поручений, ответственных и сроков; саммари; проверка фактов по транскрипту; эталонные примеры и метрики. Сохранять цитату и таймкод как доказательство, не допускать выдуманных имён и сроков. | `python scripts/evaluate.py` проверяет эталонные задачи; поручения содержат ответственного/срок либо честное «не указан», саммари соответствует записи, неподтверждённые выводы помечены для проверки. | **Реализовано, качество измерено.** `app/services/extractor.py`, `app/services/deadlines.py`, `data/samples/gold.json`. README сообщает: найдено 16/16 эталонных поручений, ответственные 16/16, сроки 15/15 проверяемых. Известная ошибка оценки: одно поручение в первом примере разбито на две строки; проверить и исправить, если останется время. |
| Участник 3 — вписать имя | **Приложение, протокол и воспроизводимость.** Поток интерфейса: согласие → загрузка/запись → результат; ручная правка поручений и имён; статусы и напоминания; экспорт DOCX/PDF/CSV; инструкция установки и демонстрационный сценарий. Интегрировать результаты участников 1 и 2. | Новый участник команды по README запускает демо; можно проверить транскрипт/поручения и скачать протокол. В экспорт попадают правки, имена, казахские буквы и полный транскрипт. | **Основной сценарий реализован.** `app/main.py`, `app/services/exporter.py`, `scripts/run_demo.py`, `README.md`. Журнал разработки сообщает о проверке чистой установки на macOS M1/8 ГБ. Перед показом нужен совместный финальный прогон текущей ветки и проверка файлов экспорта. |

## Покрытие требований кейса

| Требование | Реализация | Статус |
|---|---|---|
| Русская, казахская и смешанная речь | Маршрутизация ASR в `app/services/stt.py` | Готово; проверить на демонстрационной записи |
| Диаризация и привязка поручения к говорящему | `app/services/diarize.py`, `app/services/extractor.py` | Готово; имена сопоставляются по контексту, не по биометрии |
| Поручение, ответственный, срок и саммари | Локальный агент в `app/services/extractor.py`; резолвер дат в `app/services/deadlines.py` | Готово по результатам оценки, ручная проверка результата остаётся частью сценария |
| Запись/загрузка и согласие участников | `app/main.py`, `app/services/media.py` | Готово |
| Экспорт PDF/DOCX и выгрузка поручений | `app/services/exporter.py`, `app/main.py` | Готово; CSV также доступен |
| Напоминания/статусы | Панель внутри протокола в `app/main.py` | Готово локально в текущем просмотре; рассылки ответственным нет |
| Обработка без передачи записей в облачные API | Локальные модели, loopback Ollama, локальный кэш | Готово по описанию кода и README; модели надо заранее установить |

## Что осталось команде

- Вместо номеров вписать реальные имена участников и подтвердить распределение.
- Участнику 2 проверить ошибку разбиения одного поручения на две строки в первом примере; сверить результат с `data/samples/gold.json`.
- Совместно прогнать `data/samples/synthetic_meeting.mp3` через интерфейс на машине для демо; сверить распознанные голоса, поручения, цитаты и сроки с эталоном.
- Скачать DOCX/PDF/CSV и проверить, что правки из интерфейса попали в файлы.
- Повторить запуск по README на чистом окружении, если демо будет на другом компьютере; заранее скачать модели и локальную LLM.
- Подготовить короткий питч: проблема → локальная обработка → демонстрация результата → ценность и ограничения.

Синтетическая запись разрешена кейсом. Реальную запись используйте только с согласием участников и обезличьте для демонстрации.

## За пределами обязательного MVP

Не блокируйте демо этими задачами: бот-подключение к Teams/Zoom/Google Meet, интеграция с СЭД, email/мессенджер-рассылка, голосовая идентификация участников, долговременный реестр поручений между встречами, дообучение на данных заказчика и полноценная Docker-инсталляция. Делайте их только если основной сценарий готов и осталось время.

## Тестовые примеры — не поручения команде

`data/samples/organizer_examples/meeting1.txt`, `meeting2.txt` и `data/samples/synthetic_meeting_script.txt` содержат совещания с поручениями. `data/samples/gold.json` хранит ожидаемые ответы для тестирования. Эти файлы не дообучают веса LLM: они служат тестовыми примерами для разработки инструкций и оценки результата. `CASE_TASK_MAP.md` не является реестром выполнения этих дел реальными сотрудниками.
